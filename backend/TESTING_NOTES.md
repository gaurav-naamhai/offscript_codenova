## Limits and deployment checks

- **No live accuracy or speed claim:** Hosted `/health` returned no bytes before 15 seconds and two later 20-second timeouts. The live Gemini, OCR, Supabase, Exa, and TinyFish paths, as well as end-to-end processing time, were not measured here. Local mock timing is not representative of those services. Stage and external-call timing logs can identify the bottleneck after deployment.
- **PostgreSQL publication passed.** Run `python backend/tests/postgres/verify_publication.py` from the repository root with local Docker Desktop running. The harness applies 001 then 002 on synthetic pre-migration tables in a new isolated container. PostgreSQL 16.16 with pgvector 0.8.7 passed first publication, replacement, rollback after a second chunk failed, overlapping publications, stale correction rejection, independent families across organisations, and preservation of document, chunk and audit history.
- **Legacy backfill passed on synthetic data.** Migration 001 now recognizes both `org:...|prev:...|` and `__org=...|__prev=...` metadata. Two revisions in each format retained their organisation, parent link, revision order and active state in a fresh disposable cluster. The shared database and its actual schema were not inspected in this run.
- **Approved domains:** The current data model does not supply a verified organisation-domain allowlist to claim search. Organisation-specific claims can use exact current approved internal facts. External pages without an explicitly approved domain are treated as insufficient evidence, including similarly named companies. Adding a vetted domain source is a separate product/backend decision; do not infer it from search results.
- **Conservative checks:** Exact internal-fact matching and literal expiry parsing may send paraphrases or unusual date formats to human review. A failed provider or unreadable file yields an incomplete check. Suggested corrections that fail recheck are withheld. A recheck is a preview, not approval.
- **Storage and identity:** Submissions, comments, decisions, audit events, and seeded demo identities are in memory by default and disappear on backend restart. The browser's unsent draft storage is local demo convenience, not secure storage. The certificate endpoint returns JSON with decisions and risks; it has no verifiable digital signature.
- Before deployment, verify the legacy backfill against a disposable copy of the target schema, perform an authorised active-family audit, and test the hosted API and application on a safe environment.
